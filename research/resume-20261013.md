# Continued native iOS 7.1.2 bring-up, October 13

Target remains iPhone6,2 / n53ap / 11D257. This is a research checkpoint,
**not a bootable or usable iOS release**. No guest filesystem mount, launchd,
SpringBoard, Apple app interaction, input or persistence test has passed.

## Antigravity continuation and audit

The continuation added boot-time NVRAM partitions, clock/performance/bridge
properties and experimental PMGR/GPIO/MCC/peripheral register storage. Actual
kernel drivers and corecrypto POST now execute. Generic register readback and
instantaneous power-state acknowledgement are incomplete hardware models;
quiet MMIO traces do not certify functioning peripherals.

The resumed audit corrected a 777-byte bridge literal to the exact native
776-byte copy, aligned cpu0 frequency fields with the chosen clock profile,
validated CHRP partition construction, and made `cpus=1` explicit. Clock/fuse
defaults remain emulator assumptions, not recovered device calibration.
[Loader audit](loader-calibration-audit.md) records native instruction anchors.

The UART panic scanner now retains failure across large backtraces and partial
writes. Native PMU messages can omit a newline, joining the panic header to a
driver error on one line. This observed case is recognized using the immediately
following `Debugger message: panic`; quoting a header alone is not sufficient.
QMP quit can return zero while the launcher correctly returns failure
for a real XNU panic. Each production session retains its generated RAM,
runtime DeviceTree, ANS region, boot plan, source/binary hashes and final status
under `logs/SESSION/`; later launches cannot overwrite those inputs.

## ANS reservation and original firmware

Native iBoot selector 3 supplies **ANS RAM**, not the framebuffer: iBoot writes
`arm-io/ans/region-base` and `region-size` using it. The original reservation is
PA `0x83f800000`, length 8 MiB. Diagnostic scanout now uses a separate lower
boot allocation included below `topOfKernelData`, eliminating the ANS overlap.
[Reservation evidence](native-memory-reservations.md) records the correction;
PRAM allocator protection remains an open question.

The firmware pipeline selects and decrypts exact BuildManifest iBoot, preserves
the originals and extracts its byte-exact 233472-byte ANS ARM32 firmware.
SHA256: `c066bf9d1edef96e59fe618eb30933847ba00ac82bff2b8a7b3ef0b7a32c9b7e`.
Unknown payloads or mismatched provider/configuration bounds fail explicitly.

The loader prepares the full 8-MiB region with native BSS/shared-memory zeros
and audited iBoot CisC fixups, recording every before/after field. Its runtime
DeviceTree contains the native u64 region fields; QEMU loads this additional
image into real RAM. [ANS contract](native-ans-firmware.md) distinguishes native
stores from A0/clock/debug-policy assumptions. Preparation is not execution.

The native kernel previously returned `0xe00002c7` while preparing ANS from a
zero region template. Breakpoint evidence is in
`backend/evidence/resume-20261013/ans-region-object/`. The prepared native ANS
region advances beyond that failure. The next historical AP panic was
`i2c0::_checkBusStatus SDA is stuck low ... device pmu`, captured in
`backend/evidence/resume-20261013/native-ans-run/`.

## Separate diagnostic ANS execution

Opt-in `iop-diagnostic=1` starts the original ARM32/Thumb ANS payload only when
the guest's native A7IOP driver writes its verified region/start sequence.
The diagnostic uses a provisional Cortex-A7, separate memory view and
bootstrap page-table scratch; the physical core/SRAM contracts remain unknown.
It requires single-thread TCG (`-accel tcg,thread=single`) while preserving one
application CPU. It is not enabled by the production launcher.

Runtime trace proves native mode switching, LPAE setup and an original firmware
write at Thumb PC `0x1592`. That write uses VA `0x38040024`, translating to
PA `0x208040024`. Unsupported private peripherals return a real transaction
error and the IOP enters Data Abort; no mailbox ready messages are generated.
The AP and IOP mailbox directions, interrupt controller and storage commands
still require implementation. A booting coprocessor alone would not provide a
guest disk, mount or persistent user data.

## I2C GPIO boundary

The exact original DeviceTree selects GPIO pins 80/81 for i2c0 SDA/SCL and
82/83 for i2c1. Native GPIO code samples register bit 0. Reset-to-zero general
register storage incorrectly represents low inputs after releasing the bus.
The restricted board model gives these four released lines pull-ups while
preserving output-low behavior. Pull-ups are an explicit board assumption;
pin identity and sampling ABI have native evidence.

The rebuilt backend passes this guard and reaches `i2c1::_runInterruptMode`
timeout for device `als`, with zero status/transfer/FIFO words. Evidence is in
`backend/evidence/resume-20261013/native-gpio-pullup-default/` and
`native-gpio-pullup-iop/`. Both probes return failure; the opt-in trace also
captures the independent IOP abort described above.

[I2C/GPIO contract](native-i2c-gpio-contract.md) records pin-mode transformations,
controller offsets, actual panic branches and remaining uncertainty. An idle
high line cannot stand in for a PMU acknowledgement, received byte or IRQ.
The next controller update consumes native START/address commands, returns NACK
for every unmodeled slave, keeps RX empty, implements W1C events and asserts the
corresponding masked AIC IRQ. Both buses behave independently. Reset self-clear,
IRQ-enable clearing on reset and immediate transaction timing are explicit
limited model policies. Successful transfers and slave devices are unsupported.

This eliminates the former ALS interrupt timeout. Genuine five-second probes
`native-i2c-nack-default/` and `native-i2c-nack-iop/` show PMU reads/writes returning
`0xe00002e9`, actual display/camera driver initialization attempts, and
`ASPSEPNotifier::WaitForASP - Waiting for ASPStorage`. They stop without panic
within that interval, retaining `boot_verified=false`. PMU calibration, actual
device responses and ANS mailbox execution remain open obligations.

The longer production probe then reaches a real panic at caller
`0xffffff80010a73a0`: AppleCSI(ANS) fails IOP validation with
`0xe00002d6` and `bad.ffff` version. This is the absent handshake from an
unimplemented default IOP, not evidence that the verified source bytes are
corrupt. The opt-in diagnostic also remains blocked by the known private MMIO
abort; neither mode implements a storage service. The earlier session
`logs/20261013-013829-37c9d0f2/` exposed the joined panic-header detection defect;
its historical status is not a boot result.

After correcting detection, production session
[20261013-014044-3d9dfbe1](../build/ios712-validated/logs/20261013-014044-3d9dfbe1/runtime-final.json)
records `process.phase=failed`, `kernel.phase=failed`, and an unclean stop.
Launcher exit is **1**, while QEMU's actual exit remains **0** after QMP quit.
The [retained UART](../build/ios712-validated/logs/20261013-014044-3d9dfbe1/serial.log),
registers, trace and capture are stored beside that session's checksummed inputs.
The copied final runtime matches the bundle status and the retained kernel
image checksum matches its boot plan.

Production serial also reports failure to allocate `AGXAcceleratorG4P_A0`.
Its class/driver cause remains unverified. Display driver startup messages do
not prove a compositor, scanout updates or SpringBoard rendering.

## Completion gate

The original requested outcome is still open. Next work must model the observed
controller/device transactions and ANS mailbox/interrupt/storage path, then
prove disk detection and filesystem mount with original fstab/data contents.
Only after launchd executes can service, compositor and touch/Home bring-up be
tested. Three cold boots, Notes/settings persistence and a 15-minute interactive
session require a real SpringBoard and cannot be replaced by fixture pixels.
